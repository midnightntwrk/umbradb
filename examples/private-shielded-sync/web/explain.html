How private shielded sync works

One small example chain, every step: what the wallet computes (left), what crosses the wire (center), what the server does (right). Time goes down. Run it for real on the step-by-step page.

The example chain

9 shielded outputs at positions 0–8, each a commitment c0…c8 and a ciphertext only the recipient can open. 5 spends so far, each published as a nullifier n1…n5.

The wallet

Owns output 2 (1,000 pssUSD) and output 6 (250 pssUSD). It already spent output 2: that spend published n3. It does not know any of this yet.

The server's snapshot

Taken after output 8. Read table: 9 records in a 3 × 3 grid. Nullifier table: 4 buckets. Merkle tree cut into blocks of 4 leaves. Output 9 arrives after the snapshot.

Draws the public matrix A and computes the setup data H
A is a matrix of random numbers: one row per column of the read table (3 here), and n columns (2 here, 1,024 on the real server). It is made from a random seed written in the manifest, so anyone can rebuild it and nobody downloads it. It is public: hiding a query needs a secret that only the wallet holds, not a secret A.
The setup data H = read table × A (3 rows × n) is what lets a wallet decode an answer (step 4). It is computed once per snapshot and downloaded by every wallet.

What the server learned
One file download, one read call of 3 vectors, one nullifier call of 3 vectors, one tail. The same shape for every wallet, whatever it owns.
Never sees: the keys, which outputs matched, which columns or buckets were read, which coins are spent.
